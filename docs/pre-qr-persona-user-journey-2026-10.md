**기준일: 2026-10-12 · 기준 코드: `900cba7` 이후(Space Detail 보정) · 코드 수정 없음(분석 문서)**

> 질문: **지금 SpaceCube에 실제로 있는 기능들이, 한 사람이 웹에 처음 들어와서 실제 공간의 Cube 앞에 서기까지의 경험을 이어 주고 있는가?**

> - 근거 표기: `파일:줄` = 이번에 직접 확인한 코드. **[DB]** = 2026-10-12 운영 DB를 읽기 전용으로 센 값(시연 · 더미 제외).

## 1. Executive Summary

### 한 줄 결론

> **"이야기에서 이유를 읽고 → 상세에서 그 이유를 다시 확인하고 → 저장하고 → 현장에서 Cube를 만나는" 뼈대는 이제 코드로 완성돼 있다. 끊기는 곳은 기능이 없는 곳이 아니라 ① 처음 온 사람의 첫 행동이 로그인에서 사라지는 곳, ② 저장한 뒤 다시 돌아올 계기가 없는 곳, ③ "오늘 가자"를 결정할 정보(운영시간 · 현장 Cube가 어디 있는지)가 비어 있는 곳이다.**

### 지금 규모 [DB]

| 항목 | 값 | Journey에 주는 의미 |
|---|---|---|
| 공개 공간 | **6곳**(연남 3 · 망원 2 · 용인 처인구 1) | 6곳 모두 `cubeAvailable` — 웹에서 발견하는 모든 공간이 곧 "Cube가 있는 공간" |
| 공간당 Episode | 6곳 모두 1편 | 상세의 "공간큐브가 있는 공간"에 잠긴 `EP.1 · 제목`이 항상 보인다 |
| 운영시간(`openingHours`) | **0/6** | 상세 "정보"에 운영 행이 없다 → 방문 결정은 외부 지도에 의존 |
| 운영자의 이야기(`story` 블록) · 추가 사진(`images`) | **0/6 · 0/6** | 상세의 해당 섹션이 모두 숨겨져 있다. `/cube-spaces`는 "전체 이야기를 여기서 읽을 수 있어요"라고 약속한다 |
| 공간 태그 | 0/6 | 테마 선반 · 추천 · 검색의 태그 점수가 비어 있다 |

| CURATION / PEOPLE / THOUGHT | 6 / 3 / 3편 | CURATION 6편 모두 2026-10-04 같은 날 발행. 선정 이유(note) 14/14 |
| 실사용자 / 저장 / 내 공간 기록 / 관심 지역 | 19명 / **1건** / 4건(모두 VISITED) / **0건** | 저장 → 재방문 루프와 개인화가 아직 돌지 않는다 |

### 핵심 판단 5가지

1. **Space Detail이 Journey의 허브다.** HOME · 검색 · CURATION · PEOPLE · THOUGHT · 사람 프로필 · 내 공간 지도 — 모든 경로가 결국 `/spaces/[slug]`로 모인다. 그리고 이 화면은 이번 달 개선으로 "고른 이유 → 내 상태 → 정보 → 현장 Cube → 이어지는 이야기"를 모두 갖췄다(`SpaceDetail.tsx`).
2. **저장이 "관심"과 "방문"을 잇는 유일한 경첩인데, 처음 온 사람에게는 그 경첩이 로그인에서 부러진다.** 비로그인 저장 · 다녀왔어요는 로그인 화면으로 갔다가 같은 화면으로 돌아오지만 실행되지 않는다(`SaveButton.tsx:42-44`, `SpaceRelation.tsx`의 `toLogin`).
3. **저장 다음의 "다시 떠올림"은 사용자의 기억에 맡겨져 있다.** 저장한 공간을 다시 알려 주는 장치(알림 · 이메일)가 없고(기존 알림은 방명록 반응용이며 파일럿 플래그로 기본 꺼짐 — `pilotFlags.ts`), 재방문 계기는 Instagram의 새 콘텐츠뿐인데 발행 리듬이 없다(6편 같은 날).
4. **추천과 사람은 지금 Golden Path의 주인공이 아니다.** 공간 6곳 · 태그 0 · 사용자 19명에서는 개인 정렬이 체감되지 않고, 사람(공개 프로필)은 결국 같은 6곳만 가리킬 수 있다(`publicProfile.ts:121` — 개인 기록 제외, 공개 공간만). 둘 다 **공간이 늘어난 뒤에 켜지는 기능**으로 봐야 한다.
5. **Cube 앞에 서는 순간의 준비는 절반만 돼 있다.** 웹에서 Cube 마크(`PartnerMark` = 큐브 와이어프레임)와 잠긴 Episode 제목을 이미 봤기 때문에 "아, 그거구나"는 성립한다. 하지만 **현장 어디에 Cube가 있는지, 실물이 어떻게 생겼는지**를 말하는 문장이 상세에 없다.

### TOP 3 (14장)

1. **처음 온 사람의 첫 행동 지키기** — 로그인 후 저장 · 다녀왔어요 자동 이어하기 + 콘텐츠별 공유 미리보기
2. **"오늘 가자"를 결정할 정보 채우기** — 운영시간(기존 필드) + 현장 Cube 위치 한 줄 + 비어 있는 약속 정리
3. **저장한 공간을 다시 꺼내는 순간 만들기** — 주간 CURATION 리듬(재유입 계기) + 돌아온 사용자 HOME에서 찜한 공간을 먼저

## 2. 대표 Persona

> 기능에서 거꾸로 설계했다. **지금 공개 공간이 연남 · 망원에 몰려 있고**(5/6), 유형이 독립서점 · LP카페 · 복합문화공간 · 촬영장비 숍이며, 큐레이션 제목이 "혼자 천천히 머물기 좋은 공간들", "둘이 가도 각자의 시간이 있는 곳", "생각을 정리하고 싶은 오후"인 제품이 실제로 잘 맞는 사람이다. 전략 결론(동네 깊이 — 연남 · 망원)과도 맞춘다.

| 항목 | 내용 |
|---|---|
| 이름 | **윤서** |
| 나이 | 29세 |
| 직업 · 생활 패턴 | 합정역 근처 브랜드 디자인 스튜디오 4년차. 망원동에 산다. 평일엔 야근이 잦고, **토요일 오후 2~4시간**이 온전히 자기 시간이다. 일요일은 쉬거나 본가. |
| 공간을 찾는 빈도 | 새 공간은 **한 달에 2~3곳**. 나머지 주말은 마음에 든 2~3곳을 돌아가며 간다(재방문형). |
| 누구와 가는가 | 70%는 혼자(책 · 노트 · 생각 정리). 30%는 친구 한 명 — 대화보다 각자 시간을 보내도 괜찮은 친구. |
| 현재 공간 발견 방식 | ① Instagram 저장(폴더 없이 수백 개) ② 네이버지도 별표(200개 넘음, 대부분 다시 안 봄) ③ 친구가 카톡으로 보낸 링크 ④ 동네를 걷다가 우연히. |
| 불편 | 저장은 많은데 **"왜 저장했는지"가 기억나지 않는다.** 사진이 예쁜 곳은 가 보면 붐비거나 오래 앉아 있기 어렵다. 블로그 후기는 광고인지 알 수 없다. 막상 가면 문 닫은 날인 경우가 있다. |
| 중요하게 보는 것 | 혼자 있어도 어색하지 않은가 · 오래 머물 수 있는가 · **운영자의 관점이 있는 곳인가** · 집에서 걸어갈 만한가 · 사진보다 분위기. 별점 · 순위는 믿지 않는다. |
| SpaceCube를 쓸 이유 | ① 공간마다 **"공간큐브가 고른 이유"**가 한 문장으로 붙어 있다(사진보다 이유가 먼저). ② 저장과 다녀온 기록이 **한 곳에서 지도로** 쌓인다. ③ 가 보면 그 자리에서만 열리는 **운영자의 이야기(Cube)**가 있다 — 같은 카페를 "한 번 더 알게 되는" 경험. |
| 쓰지 않을 이유 | 공간이 6곳뿐이라 "여기서 다 찾을 수 있다"는 기대는 못 한다. 그래서 SpaceCube는 **네이버지도를 대체하지 않고, 그 위에 '고른 몇 곳'을 얹는 곳**이어야 한다. |

### 이 Persona가 아닌 사람(의도적으로 제외)

- 맛집 · 핫플 정보를 빠르게 찾는 사람 → 공간 수 · 필터 · 영업 정보가 부족해 바로 이탈한다.
- 사람을 팔로우하고 피드를 소비하는 사람 → 피드 · 좋아요 · 댓글이 없다(의도).
- 여행자(1회성 방문) → 저장 → 재방문 루프가 의미 없다.

## 3. Persona의 Job To Be Done

> **"좋은 공간을 많이 알고 싶은 게 아니다. 내 토요일 오후를 맡길 만한 동네 공간을 '왜 좋은지'와 함께 알고, 마음에 든 곳을 잊지 않고 실제로 가서, 그곳을 한 번 더 깊게 알고 싶다."**

세 조각으로 나누면 SpaceCube의 기능과 1:1로 맞는다.

| Job 조각 | 지금 맡는 기능 | 상태 |
|---|---|---|
| "왜 좋은지와 함께 안다" | CURATION note → HOME · 검색 카드 이유 → Space Detail "공간큐브가 고른 이유" | **된다** (318892a 이후) |
| "잊지 않고 실제로 간다" | 저장 → HOME 찜한 공간 · 내 공간(리스트 · 지도) → Space Detail 정보 · 지도 링크 | **부분** — 첫 저장 손실, 돌아올 계기 없음, 운영시간 없음 |
| "한 번 더 깊게 안다" | 공간큐브가 있는 공간(잠긴 EP) → 현장 Cube → QR | **부분** — 기대는 만들지만 현장에서 Cube를 찾는 단서가 없음 |

## 4. 현재 SpaceCube 기능 지도

### 4-1. Journey에서 각 기능이 해결하는 문제 (한 문장씩)

| 기능 | 실제 위치 | Journey에서 해결하는 문제 |
|---|---|---|
| **HOME** | `/` (`EditorialHome.tsx`, 선반 12종 `shelfConfig.ts:26-37`) | "오늘 뭐 좀 볼까" 하고 들어온 사람에게 **고르지 않아도 고른 공간과 새 이야기를 먼저 내미는** 문제 |
| **Search** | `/search` (`spaceSearch.ts`, 지역 · 테마 랜딩) | 이미 마음속에 지역 · 공간 이름 · 취향 단어가 있는 사람이 **직접 찾아가는** 문제 |
| **CURATION** | `/curation/[slug]` (`BlockRenderer.tsx:117-138` 공간 블록 = note + 저장 + 공간 보기) | 공간 정보가 아니라 **"이런 상황엔 이곳"이라는 관점으로 공간을 처음 만나는** 문제 |
| **STORY > PEOPLE** | `/people/[slug]` ("이 사람이 머문 공간") | **운영자 · 사람을 알면 공간이 다르게 보이는** 첫 동기를 만드는 문제 |
| **STORY > THOUGHT** | `/thought/[slug]` | 공간을 보는 **관점 자체**에 공감하게 만들어 브랜드를 신뢰하게 하는 문제(공간 발견은 보조) |
| **Space Detail** | `/spaces/[slug]` (데스크톱은 `@modal` 창, 휴대폰은 페이지) | 어디서 왔든 **"이 공간을 왜 골랐고, 나와는 어떤 관계이고, 어떻게 가고, 가면 무엇이 있나"**를 한 화면에서 판단하는 문제 |
| **Save** | `SaveButton` (카드 모서리 · 공간 블록 · 상세 내 공간 줄) | 마음이 움직인 순간을 **잊지 않게 붙잡는** 문제 |
| **Archive (내 공간)** | `/archive` 리스트 · `/archive/p/[key]` 상세 | 가보고 싶은 곳 · 다녀온 곳 · 또 간 곳을 **한 곳에 쌓아 다시 꺼내 보는** 문제 |
| **Archive Map** | `/archive?mode=map` (`ArchiveMap.tsx`, 마커 3종) | 저장 · 방문한 곳이 **내 생활 반경 어디에 있는지** 보고 "이번 주는 저쪽"을 정하는 문제 |
| **Recommendation** | HOME "엄선한 공간" · 관심 지역 선반 (`rankCandidates`, 이미 아는 곳 제외) | 내 저장 · 방문을 바탕으로 **아직 모르는 공간의 순서를 바꾸는** 문제 |
| **관심 지역** | 별표(`RegionStar`) → HOME "관심 지역에서 발견한 공간" | 내가 주로 다니는 동네의 공간을 **먼저 보이게** 하는 문제 |
| **비슷한 사람** | HOME 사람 줄 · `/@handle` 공개 프로필 · `/find?tab=people` | 나와 겹치는 공간을 고른 사람을 통해 **내가 모르는 공간으로 건너가는** 문제 |
| **관련 공간** | 상세 "함께 소개된 공간"(같은 큐레이션 우선, 없으면 같은 지역 — `relatedSpacesFor`) | 한 공간에서 **같은 관점의 다음 공간으로 이어지는** 문제 |
| **외부 지도** | 상세 "지도에서 보기 ↗"(`MapLink`, MAP_CLICK 계측) | 운영시간 · 길찾기 · 최신 정보를 **신뢰할 수 있는 지도 앱에 맡기는** 문제 |
| **Partner** | `PartnerMark`(큐브 와이어프레임) · 상세 "공간큐브가 있는 공간" · `/cube-spaces` | "이곳에 가면 **웹에 없는 경험이 있다**"를 방문 전에 알려 주는 문제(등급 · 순위가 아님) |
| **Cube** | 현장 실물 + QR → `/c/[code]` → 대표 Episode | 실제로 도착한 사람에게 **그 자리에서만 열리는 이야기**를 주는 문제 — 웹 Journey의 도착점 |

### 4-2. 한 장 지도 (QR 직전까지)

```text
  [유입]  Instagram · 카톡 공유 · 검색엔진 · 북마크
     │        (공유 미리보기: 사이트 공통 제목/설명만, 이미지 없음 — layout.tsx:12-29)
     ▼
  [콘텐츠]  /curation/[slug] ── /people/[slug] ── /thought/[slug]
     │        공간 블록: 사진 · 이름 · PartnerMark · note · 저장 · "공간 보기 →"
     ▼
  [허브]  HOME (/)  ⇄  검색 (/search)
     │     엄선 · 찜 · 지역 · CURATION · 테마 · STORY · 다시 떠올려볼 · 함께한 공간 · 사람 줄
     ▼
  [결정 화면]  Space Detail (/spaces/[slug])
     │     사진 → 이름 · 한 줄 → 내 공간 줄(저장 · 다녀왔어요/또 갔어요 · 내 기록)
     │     → 공간큐브가 고른 이유 → 공간 소개 → 정보(주소 · 지도 ↗) → 공간큐브가 있는 공간(잠긴 EP.1)
     │     → 이 공간이 소개된 이야기(가로 줄) → 함께 소개된 공간(가로 줄)
     ▼
  [붙잡기]  저장 ── 비로그인: /login → 돌아오지만 저장 안 됨 ✗
     │
     ▼
  [쌓기]  내 공간 (/archive) 리스트 | 지도 · HOME "내가 찜한 공간"
     │
     ┊  (다시 떠올리는 계기 — 저장 리마인더 없음, 발행 리듬 없음) ┊
     ▼
  [결정]  Space Detail 재방문 → 지도에서 보기 ↗ (운영시간은 외부 지도에서)
     ▼
  [현실]  실제 방문 → 공간 안에서 Cube 발견 → 카메라 앱으로 QR ── (이 문서는 여기까지)
```

## 6. Golden Path — 윤서의 2주

> 가장 이상적인 경로를 **지금 코드가 실제로 지원하는 화면 이름**으로 하나로 이었다. 각 단계 7가지: ① 상황 ② 생각 ③ 보는 화면 ④ 쓰는 기능 ⑤ 다음 행동 ⑥ 잘 되는 점 ⑦ 끊기거나 보완할 점.

### 6-1. 웹 진입 (월요일 밤, 침대에서)

1. **상황**: 퇴근 후 Instagram을 넘기다가 공간큐브 계정의 "혼자 천천히 머물기 좋은 공간들" 게시물(사진 4장 + 한 문장)을 본다. 망원 · 연남이라 집에서 가깝다.
2. **생각**: "사진 예쁜 카페 말고, 진짜 혼자 오래 있을 데 없나? 여기 다 우리 동네네."
3. **화면**: Instagram 프로필 링크 → 휴대폰 브라우저.
4. **기능**: 없음(SpaceCube 바깥). 도착 페이지가 무엇이냐가 전부다.
5. **다음 행동**: 링크 탭 → `/curation/[slug]`.
6. **잘 되는 점**: 웹이 원본이고 Instagram은 파생본이라는 구조가 맞다. 도착 페이지에 게시물보다 많은 이유(note)가 있다.
7. **보완**: 친구에게 카톡으로 다시 공유하면 미리보기가 **이미지 없는 사이트 공통 문구**다(G3). 유입 출처를 기록하지 않아 이 경로가 몇 번 일어났는지 셀 수 없다.

### 6-2. 콘텐츠 (같은 밤, 3분)

1. **상황**: 큐레이션 본문을 위에서부터 읽는다. 진행 막대가 줄어드는 게 보인다.
2. **생각**: "아, 이 서점은 '예약하고 가는 곳'이라서 조용하구나. 이유가 납득된다."
3. **화면**: `/curation/[slug]` — 리드, 공간 블록 4개(사진 · 이름 · 큐브 마크 · note · 저장 · 공간 보기).
4. **기능**: CURATION + 공간 블록의 note(선정 이유).
5. **다음 행동**: 북눅 연남 블록의 **"공간 보기 →"**.
6. **잘 되는 점**: 공간명보다 **"왜 골랐는지"가 먼저 읽힌다.** note 14/14가 채워져 있다. 블록에 저장 버튼이 바로 있어서 "나중에"의 마음을 그 자리에서 붙잡을 수 있다.
7. **보완**: 공간 블록의 큐브 마크(작은 아이콘)는 아직 뜻을 모른다 — 툴팁("공간큐브가 있는 공간")은 휴대폰에서 보이지 않는다. 여기서는 몰라도 괜찮다(상세에서 문장으로 풀린다).

### 6-3. 공간 발견 → Space Detail (같은 밤)

1. **상황**: 상세 페이지가 열린다(휴대폰 = 페이지, 맨 위에서 시작).
2. **생각**: "읽은 그 이유가 여기에도 있네. 주소가… 망원에서 걸어서 20분. 갈 만하다."
3. **화면**: `/spaces/booknook-yeonnam` — 사진 → 연남 · 독립서점 · 큐브 마크 → 이름 · 한 줄 → [저장하기][다녀왔어요] → **공간큐브가 고른 이유**(같은 note + "혼자 천천히 머물기 좋은 공간들 →") → 공간 소개 → 정보(지역 · 종류 · 주소 · 지도에서 보기 ↗) → **공간큐브가 있는 공간**("현장에서 QR을 찍으면 이 공간의 Episode가 열려요." + `EP.1 · 나만의 작은 구석 🔒`) → 이 공간이 소개된 이야기(7편 가로 줄) → 함께 소개된 공간(3곳).
4. **기능**: Space Detail, 고른 이유(`pickSpaceReasons`), PartnerEpisodeList, DetailRail, 관련 공간(`relatedSpacesFor`).
5. **다음 행동**: 잠긴 EP를 눌러 본다 → "이 이야기는 공간에서 열 수 있어요. 공간을 방문해 공간큐브의 QR을 인식해보세요." → 확인 → **저장하기**.
6. **잘 되는 점**: **이유가 화면을 넘어와도 따라온다**(P2 — 10/12 Gap의 G1 해소). "가면 여기서만 열리는 이야기가 있다"가 방문 전에 보인다 — 다른 지도 서비스 상세에 없는 정보.
7. **보완**: 운영시간 행이 없다(0/6). 운영자의 이야기 · 사진 묶음 섹션은 데이터가 없어 통째로 숨겨져 있다(0/6). 잠긴 EP 안내 창은 "확인"뿐이라 **Cube가 공간 어디에, 어떤 모양으로 있는지**를 말하지 않는다. 맨 아래 "더 많은 공간 이야기는 Instagram에서 →"는 막 도착한 사람을 다시 내보낸다.

### 6-4. 저장 (같은 밤 — 첫 번째 큰 끊김)

1. **상황**: 비로그인. 저장하기를 누른다.
2. **생각**: "일단 담아 두자."
3. **화면**: `/login?callbackUrl=/spaces/booknook-yeonnam` — "로그인하고 …" + 카카오 · Google.
4. **기능**: SaveButton(비로그인 → 로그인 이동), 로그인 후 같은 주소로 복귀.
5. **다음 행동**: 카카오로 로그인 → 상세로 돌아옴 → **저장 아이콘은 비어 있다** → (알아채면) 다시 누름 / (못 알아채면) 저장된 줄 알고 닫음.
6. **잘 되는 점**: 로그인 후 같은 화면으로 돌아온다. 소셜 로그인 두 가지로 가입이 짧다.
7. **보완**: **저장 의도가 로그인에서 사라진다**(`SaveButton.tsx:42-44` — 이동만 하고 의도를 싣지 않음). 다녀왔어요도 같다(`SpaceRelation`의 `toLogin`). 첫 방문자의 첫 행동이 가장 높은 확률로 손실되는 지점이고, 손실을 사용자도 운영자도 모른다.

### 6-5. 내 공간 (다음 날 점심, 회사에서)

1. **상황**: 어제 저장한 게 생각나서 SpaceCube를 다시 연다(브라우저 기록).
2. **생각**: "어제 그 서점 이름이 뭐였지? 저장했었나?"
3. **화면**: HOME → "내가 찜한 공간" 선반, 또는 하단 탭 **내 공간** → `/archive` "가보고 싶은 곳 1".
4. **기능**: HOME saved 선반, Archive 리스트(전체 · 다녀온 곳 · 가보고 싶은 곳, 이름 검색 · 지역).
5. **다음 행동**: 타일 → 내 기록(`/archive/p/s-booknook-yeonnam`) → "공간큐브에서 이 공간 보기 →" → 상세.
6. **잘 되는 점**: 저장이 제대로 됐다면 HOME과 내 공간 두 곳에서 바로 보인다. 웹 저장 · Cube 방문 · 직접 추가가 한 그리드에 모인다(`library.ts`).
7. **보완**: 6-4에서 저장이 손실됐다면 여기서 **빈 화면**을 만난다 — "저장 안 됐네" 하고 신뢰가 깎인다. 타일에는 **왜 저장했는지**(어느 큐레이션에서 왔는지)가 남지 않는다(`SavedEditorialSpace` = userId · spaceId · createdAt).

### 6-6. 다시 떠올림 (목요일 밤 — 두 번째 큰 끊김)

1. **상황**: 토요일 계획을 세운다. 이 단계는 **사용자의 기억이나 외부 자극이 있어야만** 일어난다.
2. **생각**: "이번 토요일 오후 어디 가지… 아, 그 서점 저장해 뒀었지."
3. **화면**: (기억이 나면) HOME 또는 내 공간 → **지도**(`/archive?mode=map`).
4. **기능**: Archive Map — 가보고 싶은 곳(속 빈 마커) · 다녀온 곳 · 또 간 곳.
5. **다음 행동**: 연남 쪽 마커 → 카드 "공간 보기" → 상세.
6. **잘 되는 점**: 지도에서 내 동네(망원)와 저장한 곳(연남)의 거리가 한눈에 보인다 — **"이번 주는 연남 쪽"**을 정하는 데 실제로 쓸모 있다. 검색 지도가 아니라 내 기록 지도라 6곳이어도 빈약해 보이지 않는다.
7. **보완**: **돌아올 계기가 SpaceCube 안에 없다.** 저장한 공간을 다시 알려 주는 알림 · 이메일이 없고, 새 CURATION도 10/04 이후 없다. 윤서가 기억하지 못하면 이 단계는 일어나지 않고, 저장은 네이버지도 별표처럼 묻힌다.

### 6-7. 추천 또는 사람 (목요일 밤, 선택적)

1. **상황**: 서점 하나만 가기엔 아쉬워서 근처에 한 곳 더 볼까 한다.
2. **생각**: "서점 갔다가 커피 한 잔 할 데 없나? 비슷한 결로."
3. **화면**: 상세 "함께 소개된 공간"(턴다운서비스 · 인너디스커버리 …) 또는 HOME "회원님을 위해 엄선한 공간".
4. **기능**: 관련 공간(같은 큐레이션 우선), 엄선 선반(저장 · 방문 제외 후 개인 정렬, 카드 이유 = note 우선).
5. **다음 행동**: 턴다운서비스(LP카페, 연남) → 상세 → 고른 이유 "대화보다 음악이 먼저 들리는 곳" → 저장.
6. **잘 되는 점**: **같은 관점(큐레이션)으로 묶인 공간**이 다음 후보로 나온다 — "근처"가 아니라 "결이 같은 곳". 실제로 이 연결이 지금 가장 잘 작동하는 '추천'이다.
7. **보완**: HOME 엄선 선반은 제목이 "회원님을 위해"로 바뀌지만(저장 1건이면 `personalized=true`), 태그 0 · 유형이 공간마다 달라 순서는 거의 그대로다 — **말은 개인화, 체감은 큐레이션 순**. 사람 줄과 "비슷한 사람들이 좋아한 공간"은 겹치는 사용자가 2명 이상일 때만 나오므로(`EditorialHome.tsx` · `homeData.ts`) 이 시점의 윤서에게는 대부분 보이지 않는다.

### 6-8. 방문 결정 (토요일 오전)

1. **상황**: 날씨 좋음. 오후 2시쯤 나갈 생각.
2. **생각**: "오늘 여나? 몇 시까지 하지? 혼자 가도 자리 있겠지?"
3. **화면**: 내 공간 지도 또는 HOME 찜 선반 → 상세 → **정보**.
4. **기능**: 정보(지역 · 종류 · 주소), 공간큐브가 있는 공간, 고른 이유(다시 읽기).
5. **다음 행동**: **지도에서 보기 ↗**.
6. **잘 되는 점**: 고른 이유를 다시 읽으며 "그래서 가려던 거였지"가 회복된다. Cube 섹션이 **"가면 하나 더 있다"**는 마지막 한 표를 보탠다.
7. **보완**: 운영시간 · 휴무가 SpaceCube에 없다 → 결정의 마지막 정보를 외부 지도에서 확인해야 한다. 혼자 가도 되는지 · 오래 머물러도 되는지는 note에만 있고 태그(상황 언어)는 비어 있다.

### 6-9. 외부 지도 (토요일 오전)

1. **상황**: 네이버지도가 열린다.
2. **생각**: "12시 오픈, 월요일 휴무. 걸어서 22분. 좋아."
3. **화면**: 외부 지도 앱(`space.mapUrl`).
4. **기능**: MapLink(MAP_CLICK 계측 — 관리자 KPI의 "지도 클릭 → 7일 내 QR" 전환에 쓰임).
5. **다음 행동**: 길찾기 → 출발.
6. **잘 되는 점**: 영업 정보 · 길찾기를 **직접 만들지 않고 신뢰할 수 있는 앱에 맡긴다** — 지도 경쟁을 하지 않는 올바른 선택.
7. **보완**: 지도 앱으로 넘어간 뒤 SpaceCube로 돌아올 다리가 없다. 다만 이건 자연스럽다 — 이 시점의 SpaceCube 역할은 끝났고, 다음 역할은 현장 Cube다.

### 6-10. 실제 방문 (토요일 오후 2시 20분)

1. **상황**: 서점에 들어간다. 조용하다. 책을 고르고 자리를 잡는다.
2. **생각**: "진짜 그 이유 그대로네. 혼자 와도 편하다."
3. **화면**: 없음(현실). 휴대폰은 가방 안.
4. **기능**: 없음. **웹에서 읽은 note가 현실과 맞는지가 신뢰를 결정한다.**
5. **다음 행동**: 머문다. 30분쯤 지나 주변을 둘러본다.
6. **잘 되는 점**: 큐레이션이 실제 경험과 맞으면 SpaceCube에 대한 신뢰가 생긴다(별점보다 강한 신뢰).
7. **보완**: (방문 중 기록) 상세의 "다녀왔어요"는 로그인 사용자만 바로 된다. 하지만 이건 QR 이후 Record와 겹치는 영역이라 이 문서에서는 다루지 않는다.

### 6-11. Cube 발견 (토요일 오후 2시 50분)

1. **상황**: 계산대 옆(가정) 선반에서 작은 큐브를 본다.
2. **생각**: **"아, 웹에서 봤던 공간큐브가 이거구나. 잠겨 있던 EP.1이 여기서 열리는 거지?"**
3. **화면**: 현장 실물 Cube(QR · GC 코드 스티커).
4. **기능**: 웹에서 미리 본 것 — 카드의 큐브 마크(`PartnerMark` = 큐브 와이어프레임), 상세 "공간큐브가 있는 공간" 문장, 잠긴 `EP.1 · 제목`, 잠금 안내 창, HOME 하단 Experience(DISCOVER → SAVE → VISIT → CUBE → RECORD) · `QrScanSheet`.
5. **다음 행동**: 카메라 앱을 열어 QR을 비춘다.
6. **잘 되는 점**: 웹에서 **제목까지 보고 잠겨 있던 이야기**가 있으니 "열어 보고 싶다"는 이유가 이미 만들어져 있다(Adventure Lab의 "도착해야 열림" 원리). 브랜드 마크와 실물이 같은 도형이라 인식이 이어진다.
7. **보완**: Cube가 **공간 어디에 있는지**는 웹 어디에도 없다. 찾지 못하면 이 단계 자체가 일어나지 않는다. 카메라 앱으로 찍어야 한다는 안내(`QrScanSheet`)는 HOME 맨 아래에만 있고 상세 · 잠금 안내 창에는 없다.

### 6-12. QR 직전 (이 문서의 마지막 장면)

윤서는 이미:

- 이 공간을 **왜 골랐는지** 안다 — CURATION note를 두 번(콘텐츠 · 상세) 읽었다.
- **저장했다**(로그인 벽에서 한 번 놓칠 뻔했다).
- **Space Detail을 두 번** 봤다 — 발견할 때, 출발하기 전.
- **실제로 와서** 그 이유가 맞다는 걸 확인했다.
- 그리고 웹에서 잠겨 있던 **EP.1 제목**을 기억한다.

> "아, 웹에서 봤던 공간큐브가 이거구나." → 카메라를 든다 → **QR Scan**

## 7. 신규 사용자 Journey

```text
Instagram 게시물
→ /curation/[slug]          "이유가 있네"
→ 공간 블록 "공간 보기 →"
→ /spaces/[slug]             "읽은 이유가 여기도 있고, 가면 열리는 이야기도 있네"
→ 저장하기 → /login → 복귀   "저장… 됐나?"  ← 손실 지점
→ (며칠 뒤, 기억이 나면) HOME 찜한 공간 · 내 공간
→ /spaces/[slug] → 지도에서 보기 ↗
→ 실제 방문 → Cube → QR
```

| 단계 | 현재 기능이 신규 사용자를 지원하는 방식 | 빈 곳 |
|---|---|---|
| 도착 | 콘텐츠 · 상세 모두 로그인 없이 전부 열린다(벽 없음) | 공유 미리보기 · 유입 출처 |
| 이해 | 고른 이유 · Cube 섹션 · HOME Experience가 서비스 소개를 대신한다 | 큐브 마크의 뜻은 상세에 가야 문장으로 나온다 |
| 첫 행동 | 저장 · 다녀왔어요 → 로그인 → 같은 화면 | **의도 손실** |
| 재방문 | 브라우저 기록 · 북마크에 의존 | 계기 없음 |
| 추천 · 사람 | 데이터가 없어 보이지 않음(정상) | — |

**신규 사용자에게 SpaceCube는 "잘 고른 매거진 + 현장에 무언가 있는 곳"이다.** 추천 · 사람 · 지도는 아직 의미가 없고, 의미가 있어서도 안 된다.

## 8. 기존 사용자 Journey

```text
HOME (/)
→ 내가 찜한 공간 / 다시 떠올려볼 공간       "그때 그곳"
→ 내 공간 (/archive) → 지도 (?mode=map)      "이번 주는 연남 쪽"
→ 엄선한 공간 · 함께 소개된 공간            "결이 같은 곳 하나 더"
→ (조건 충족 시) 취향이 비슷한 사람 → /@handle → 공간 → /spaces/[slug]
→ 새로운 공간 → 지도에서 보기 ↗ → 방문 → Cube → QR
```

| 단계 | 현재 기능 | 기존 사용자에게의 실제 가치 |
|---|---|---|
| HOME | 엄선(아는 곳 제외) · 찜 · 다시 떠올려볼 · 관심 지역 · 비슷한 사람 | 찜 · 다시 떠올려볼은 **가치 있음**. 엄선은 6곳 풀에서 남은 2~4곳 — 매번 같다 |
| 내 공간 | 리스트(상태 3종) · 지도 · 공간별 방문 타임라인(웹 + Cube) | **가장 가치 있음** — 쌓인 게 보인다 |
| 추천 | 개인 정렬 · 이유 문구 | 체감 없음(태그 0 · 공간 6) |
| 사람 | 겹친 공간 이름 이유("북눅을 함께 다녀왔어요"), 공개 프로필 | 결국 같은 6곳 중 하나를 가리킴 — **새 공간 발견 불가** |
| 새로운 공간 | 새 CURATION · 새 공개 공간 | **공급이 유일한 해법** — 지금 새 공간이 없다 |

### 두 Journey를 다르게 지원하는가?

- **다르게 지원한다(구조상).** 비로그인 · 신호 없음 → "공간큐브가 엄선한 공간"(큐레이션 순) + 찜 선반 자리에 로그인 안내 카드. 로그인 · 신호 있음 → "회원님을 위해" + 찜 · 다시 떠올려볼 · (관심 지역 · 비슷한 사람).
- **하지만 기존 사용자에게 "새로움"을 주는 장치는 전부 공급(공간 · 콘텐츠 수)에 묶여 있다.** 개인화 · 사람 · 관심 지역이 모두 "아직 모르는 공간"을 전제로 하는데, 6곳에서는 그 집합이 거의 비어 있다.

## 9. 기능별 Persona Scenario

### HOME

- **들어오는 이유**: (기존 사용자) 이번 주말 갈 곳을 고르거나 저장한 곳을 다시 찾으려고. (신규) 콘텐츠 하단 · 로고를 눌러서.
- **하는 행동**: 위 3개 선반까지 훑기 → 카드 하나 탭 → 상세. 지역 선택(망원)을 한 번쯤 눌러 본다.
- **성공**: 첫 화면 2스크롤 안에서 "가볼 만한 곳" 하나를 상세로 연다. 찜한 공간을 3초 안에 찾는다.
- **현재 문제**: 비로그인 HOME에서 같은 6곳이 엄선 · 새로 소개 · 지역 · 함께한 공간 선반에 반복된다(다양성 재정렬로 줄였지만 풀 자체가 6곳). 돌아온 사용자에게 "새 것"이 없다. 엄선 "더 보기"가 메뉴에 없는 `/find`(탐색)로 간다.
- **개선**: 규모에 맞게 선반 접기(관리자 선반 토글로 바로 가능), 로그인 + 저장 있음일 때 찜한 공간을 먼저, CURATION 선반을 공간 선반보다 위로.

### Search

- **들어오는 이유**: 친구에게 들은 공간 이름 · "연남" · "LP" 같은 단어가 머릿속에 있을 때.
- **하는 행동**: 입력 → 공간 결과(카드 이유 = note) → 상세. 검색어 없이 들어오면 추천 지역 · 테마 칩.
- **성공**: 이름 · 지역 · 유형으로 2타 안에 원하는 공간이 맨 위.
- **현재 문제**: 공간이 6곳이라 Persona가 Search를 쓸 이유가 약하다(HOME에서 다 보인다). 테마 검색("혼자", "대화")은 태그 0이라 큐레이션 문장 · 설명에 걸릴 때만 나온다.
- **개선**: 코드보다 운영 — 공간 태그 3~5개 입력. Search는 공간이 20곳 이상일 때 주인공이 된다.

### Curation

- **들어오는 이유**: Instagram · HOME CURATION 선반. "이런 상황에 갈 곳"이라는 관점이 궁금해서.
- **하는 행동**: 끝까지 읽기 → 공간 블록 "공간 보기" · 저장 → 관련 큐레이션.
- **성공**: 한 편에서 공간 1곳 이상 상세로 이동 + 1곳 저장.
- **현재 문제**: 6편이 같은 날 발행돼 **리듬이 없다**. 공유 미리보기 없음. 비로그인 저장 손실.
- **개선**: 주 1편 리듬(운영), 콘텐츠별 og 메타(작은 코드), 저장 의도 보존(작은 코드).

### People (사람 · 공개 프로필)

- **들어오는 이유**: HOME "취향이 비슷한 사람" 줄의 아바타, 친구가 보낸 `/@handle` 링크.
- **하는 행동**: 프로필 → 다녀온 공간 · 가보고 싶은 공간 그리드 → 카드 → 그 사람의 기록(`/@handle/s/[slug]`) → "공간 자세히 보기 →" → 상세.
- **성공**: 프로필에서 **내가 아직 모르는 공간 1곳**을 상세로 연다.
- **현재 문제**: 공개 프로필은 공개 공간(지금 6곳)만 보여준다(`publicProfile.ts:121`) → 6곳 중 내가 아는 곳이 대부분이면 프로필은 "나도 담은 곳" 표시만 가득하다. 다녀온 → 가보고 싶은 순서가 고정이라 **모르는 공간이 먼저 오지 않는다.** 프로필 첫 줄에 따라가기 · 팔로워 수가 있다(사람을 소비하는 요소).
- **개선**: NEXT — 프로필에서 "내가 아직 모르는 공간" 먼저, 선반 이유에 공개 @handle. 지금은 강조하지 않는다(11장 참고).

### Space Detail

- **들어오는 이유**: 모든 경로의 도착점. 처음엔 "어떤 곳이지?", 두 번째엔 "오늘 갈까?"
- **하는 행동**: 사진 → 고른 이유 → 주소 → 저장 / 지도 ↗ / 잠긴 EP 탭 / 이야기 줄 · 함께 소개된 공간.
- **성공**: 첫 방문 → 저장. 두 번째 방문 → 지도 ↗.
- **현재 문제**: 운영시간 0/6, 운영자 이야기 · 사진 0/6, Cube 위치 안내 없음, 맨 아래 Instagram 링크가 사용자를 내보냄, 비로그인 저장 · 다녀왔어요 손실.
- **개선**: 정보 채우기(운영), 잠금 안내 창에 Cube 찾는 법 한 줄, Instagram 링크 제거, 의도 보존.

### Save

- **들어오는 이유**: "나중에 가 보고 싶다"는 마음이 생긴 순간 — 공간 블록 · 카드 모서리 · 상세 내 공간 줄.
- **하는 행동**: 탭 → 아이콘이 채워진다(로그인 시 낙관적 표시 + 서버 확정).
- **성공**: 한 번 탭으로 담기고, HOME · 내 공간 · 지도에 즉시 나타난다.
- **현재 문제**: 비로그인 의도 손실. 저장한 맥락(어느 큐레이션에서) 미기록.
- **개선**: 의도 보존(NOW). 맥락 기록은 스키마 결정이 필요 — NEXT.

### Archive (내 공간)

- **들어오는 이유**: 저장한 곳 다시 찾기, 이번 주 갈 곳 정하기, 다녀온 곳 돌아보기.
- **하는 행동**: 가보고 싶은 곳 탭 → 타일 → 내 기록 → "공간큐브에서 이 공간 보기" → 상세.
- **성공**: 저장한 곳에서 상세 · 지도 ↗까지 3탭 이내.
- **현재 문제**: 비로그인으로 하단 탭 "내 공간"을 누르면 곧바로 로그인 화면이다(무엇을 주는 곳인지 보기 전). 타일에 시간 정보 · 저장 맥락이 없다. 가보고 싶은 곳 → 내 기록 → 상세 → 지도로 한 단계가 더 있다.
- **개선**: NEXT — 타일에 "가보고 싶어요 · 10월 4일 저장"(맥락은 스키마 이후). 가보고 싶은 곳 타일은 내 기록 대신 상세로 바로(지도 카드는 이미 그렇게 함).

### Archive Map

- **들어오는 이유**: "이번 주말엔 어느 쪽으로 갈까" — 저장한 곳이 3곳 이상 쌓인 뒤.
- **하는 행동**: 지도 탭 → 마커(가보고 싶은 곳 · 다녀온 곳 · 또 간 곳) → 카드 → 가보고 싶은 곳은 "공간 보기"(상세), 다녀온 곳은 "내 기록 보기".
- **성공**: "망원 집에서 연남 두 곳을 묶어 가자"를 지도 한 화면에서 정한다.
- **현재 문제**: 저장 1~2곳일 때는 지도가 쓸모없다(그럴 때는 리스트가 낫다). 위치 권한 · 내 위치 · 거리가 없다 — **의도된 한정**이며 맞다.
- **개선**: 없음(지금 역할이 맞다). LATER — 마커 카드에 "마지막 방문 · N번", 기간 축.

### Recommendation

- **들어오는 이유**: 직접 찾으러 가지 않는다. HOME 엄선 선반의 순서와 카드 이유로만 만난다.
- **하는 행동**: 엄선 카드 이유를 읽고 탭.
- **성공**: "다녀온 북눅과 같은 독립서점" 같은 **이름 있는 이유**로 새 공간 하나를 연다.
- **현재 문제**: 이유 문구가 "내 공간들과 비슷한 결" 고정이고, 그나마 큐레이션 note에 가려져 화면에 나오지 않는다(`homeData.ts`의 `cardOfRanked`). 저장 1건이면 제목만 "회원님을 위해"로 바뀐다.
- **개선**: NEXT — 공간 20~30곳 · 태그 입력 이후. 그 전까지는 제목을 "공간큐브가 엄선한 공간"으로 유지하는 쪽이 정직하다(13장 후보).

### Cube

- **들어오는 이유(웹에서)**: 상세의 잠긴 EP, 큐브 마크, HOME Experience, `/cube-spaces`.
- **하는 행동(현장에서)**: 실물 Cube 발견 → 카메라 앱 → QR.
- **성공**: 도착 후 Cube를 **찾아다니지 않고** 발견한다. 그리고 "웹에서 본 그거"로 인식한다.
- **현재 문제**: 현장 위치 · 실물 모양 안내 없음. 카메라 앱 안내는 HOME 맨 아래에만. `/cube-spaces`가 약속한 "운영자의 이야기"는 6곳 모두 비어 있다.
- **개선**: 잠금 안내 창 · Cube 섹션에 "카운터 옆 작은 흰 큐브" 같은 위치 한 줄 + "카메라 앱으로 비춰 주세요". 운영자 이야기가 없는 동안은 `/cube-spaces` 문구를 실제와 맞춤.

### 12-2. People이 SNS로 변질되지 않는가 (B-11)

**구조상으로는 변질되지 않았다.** 피드 · 좋아요 · 댓글 · DM이 없다. HOME 사람 줄은 아바타 + 이름뿐이고 숫자가 없다(`SimilarPeopleShelf.tsx`). 사람 추천 이유도 사람이 아니라 **겹친 공간 이름**이다("북눅을 함께 다녀왔어요", `rankPeople.ts:47-58`). 프로필 카드에서 저장 아이콘과 "공간 자세히 보기"로 바로 공간에 닿는다.

**하지만 Persona 관점의 역할 — "나와 비슷한 사람이 다녀온, 내가 모르는 공간 발견" — 은 지금 작동하지 않는다.**

1. **가리킬 공간이 없다.** 공개 프로필은 공개 공간만 보여준다(`publicProfile.ts:121`, 개인 기록 · 시연 제외). 공개 공간이 6곳이면 어떤 사람의 프로필도 그 6곳의 부분집합이다. 비슷한 사람일수록 내 공간과 겹치므로, **비슷할수록 새로운 것이 없다**는 역설이 생긴다.
2. **모르는 공간이 먼저 오지 않는다.** 다녀온 공간 → 가보고 싶은 공간 순서 고정, "나도 담은 곳" 라벨은 아는 곳을 강조한다.
3. **사람을 소비하는 요소가 프로필 첫 줄에 있다.** 따라가기 버튼 · 팔로잉/팔로워 수(`ProfileFollowArea`, `RelationLine`). 따라가기는 Golden Path 어디에도 다시 쓰이지 않는다.
4. **HOME 공간 선반은 누가 골랐는지 숨긴다**("나와 비슷한 취향의 사용자가 다녀온 공간"). 사람의 신뢰가 공간으로 옮겨 가지 못한다.

> **판단: People은 "SNS"도 "공간 발견"도 아닌 휴면 상태다.** 공간이 지역당 10곳 이상이 되기 전까지는 강조하지 말고(지금처럼 HOME 맨 아래 · 조건부), 그때 ① 모르는 공간 먼저 ② 선반 이유에 공개 @handle ③ 프로필 숫자를 첫 줄에서 내림 — 세 가지를 함께 켠다.

### 12-3. Archive Map의 역할 (B-12)

- **역할은 맞게 한정돼 있다.** 위치 권한 · 내 위치 · 주변 검색 · 거리순이 없고(`ArchiveMap.tsx`), 마커는 내가 저장 · 방문한 곳뿐이다. "지도에서 새 공간 찾기"가 아니라 **"내가 저장하고 머문 공간이 지도에 쌓이는 경험"**이다.
- **Golden Path에서 볼 가능성이 높은 순간은 두 번이다.**
  1. **6-6 다시 떠올림(목요일 밤)** — 저장이 3곳 이상일 때 "이번 주말엔 어느 쪽"을 정하는 계획 도구. 저장 1~2곳이면 리스트가 낫다.
  2. **방문 후 회고**(QR 이후, 이 문서 범위 밖) — 다녀온 곳 · 또 간 곳이 쌓여 "내가 머문 동네"가 보이는 순간. 이 기능의 진짜 가치는 이쪽이다.
- 신규 사용자에게 지도는 의미가 없다(마커 0~1개). 그래서 내 공간의 기본 보기가 리스트인 지금 구성이 맞다.

### 12-4. Recommendation의 성숙 단계 (B-13)

| 단계 | 사용자 데이터 | 지금 코드가 하는 일 | 사용자가 느끼는 것 |
|---|---|---|---|
| 첫 방문(비로그인) | 없음 | "공간큐브가 엄선한 공간" = 큐레이션 · 운영 순서, 카드 이유 = note | 편집된 목록(정직함 ✓) |
| 저장 1~2곳 | 저장 신호 2점 × 유형 | `personalized=true` → 제목 "회원님을 위해 엄선한 공간", 저장한 곳은 엄선에서 빠지고 찜 선반으로 | **제목만 바뀜.** 유형이 공간마다 달라 순서 변화 거의 없음 |
| 방문 1~3곳 | 다녀왔어요 3점, Cube Record(최신 1건 × tasteScore) | 같은 유형(예: 복합문화공간 2곳)만 순서가 오름. 다녀온 곳은 "다시 떠올려볼 공간"으로 | 체감 미미 — 남은 후보가 2~4곳 |
| 재방문 | 또 갔어요(ArchiveVisit N회) | **신호로 쓰지 않음**(공간당 최신 Record 1건, 방문 횟수 무시 — 10/12 Gap D3) | 반영 안 됨 |
| 비슷한 사람 | 다른 사용자와 겹침 2명 이상 | 사람 줄 · "비슷한 사람들이 좋아한 공간" 등장 | 19명 중 겹침이 생기기 어려움 |

**언제부터 의미가 생기나:**

- **공급 조건**: 한 지역(연남 · 망원)에 공간 **10곳 이상**, 전체 20~30곳, 공간마다 태그 3~5개. 이 전에는 "아직 모르는 공간" 집합이 너무 작아 순서를 바꿔도 알아챌 수 없다.
- **사용자 조건**: 저장 · 방문 **3곳 이상, 유형 2종 이상**. 그래야 겹친 속성이 생긴다.
- **결론**: 지금 추천은 **"없어도 Journey가 끊기지 않는 기능"**이다. Golden Path의 6-7 단계에서 추천 역할은 이미 "함께 소개된 공간"(같은 큐레이션)이 하고 있고, 그게 지금 규모에 맞는 추천이다. 개인 정렬은 공간이 늘어난 뒤 이유를 이름으로 바꾸면서(NEXT) 켜는 것이 맞다.

## 14. TOP 3

> 선정 기준: QR 직전까지의 경험을 가장 크게 바꿀 것, **새 기능보다 기존 기능 연결**, 지금 데이터(공간 6 · 저장 1)에서도 의미가 있을 것, 서로 겹치지 않을 것.

### TOP 1. 처음 온 사람의 첫 행동 지키기 (후보 1 + 2)

- **어디**: 6-1 진입 → 6-4 저장. 심리 끊김 A.
- **왜 1위**: Golden Path에서 가장 많은 사람이, 가장 의욕이 높은 순간에 지나가는 곳이다. 지금은 손실이 일어나도 아무도 모른다.
- **기존 연결**: 로그인 후 같은 화면 복귀(`callbackUrl`)는 이미 있다. 그 주소에 "무엇을 하려 했는지"만 실어 보내면 된다. 공유 미리보기도 각 페이지의 기존 `generateMetadata`에 이미지 · 요약을 더하는 일이다.
- **검증**: 비로그인 저장 클릭 → 로그인 완료 → 실제 저장 비율(지금은 측정조차 안 됨).

### TOP 2. "오늘 가자"를 결정할 정보 채우기 (후보 3 + 4 + 8)

- **어디**: 6-8 방문 결정 → 6-11 Cube 발견. 심리 끊김 C · D.
- **왜 2위**: 상세가 "왜"는 이미 말한다. 이제 "언제 · 어디서(Cube는 어디에)"만 말하면 된다. 대부분 **이미 있는 필드와 문장**이다 — `openingHours`(0/6), 공간 소개 문단, 잠금 안내 창, `QrScanSheet` 문구.
- **함께 정리**: 맨 아래 Instagram 링크 제거, `/cube-spaces`의 "운영자의 이야기" 약속을 현재 데이터와 맞춤(이야기를 채우거나 문구 조정).
- **검증**: 상세 → 지도 클릭 → 7일 내 QR(관리자 KPI에 이미 있음).

### TOP 3. 저장한 공간을 다시 꺼내는 순간 만들기 (후보 5 + 6, 7은 이어서)

- **어디**: 6-5 내 공간 → 6-6 다시 떠올림. 심리 끊김 B.
- **왜 3위**: 저장은 다시 꺼낼 때 비로소 가치가 생긴다. 지금 SpaceCube 안에는 그 계기가 없고, 알림을 새로 만드는 것은 이번 원칙(새 기능보다 연결)에 맞지 않는다. **가장 싼 계기는 새 콘텐츠다** — 주 1편 CURATION이 Instagram 재유입을 만들고, 그 큐레이션 안에서 이미 저장한 공간은 저장 아이콘이 채워진 채 보인다(기존 동작). HOME은 같은 6곳의 반복 선반을 관리자 토글로 접어 "고른 것"만 남긴다.
- **이어서(작은 코드)**: 로그인 + 저장 있음일 때 찜한 공간을 HOME 첫 선반으로.
- **검증**: 저장 후 7일 내 재방문 사용자 수, 재방문 세션에서 찜 공간 상세 → 지도 클릭.

> **제외한 것**: 추천 정합화 · 사람 선반 개편(후보 10)은 방향은 맞지만 공간 6곳에서는 사용자가 차이를 느낄 수 없다. 공급(공간 · 태그 · 발행)이 먼저다.

## 15. 최종 SpaceCube Journey 정의

### 다른 서비스와 구분되는 Journey

```text
지도 · 검색 서비스:  장소 검색 → 별점 · 리뷰 비교 → 방문
SpaceCube:           이야기에서 공간을 만남 → 고른 이유에 공감 → 저장해 내 공간에 쌓음
                     → 다시 꺼내 직접 감 → 그 자리에서만 열리는 운영자의 이야기(Cube)로 공간을 한 번 더 만남
```

> **SpaceCube의 Journey: "누군가 고른 이유로 공간을 처음 만나고, 그 이유를 들고 직접 찾아가, 그 자리에서만 열리는 이야기로 그 공간을 한 번 더 알게 되는 것."**

### 이 Journey를 지금 기능이 만들어 내고 있는가?

- **뼈대: 예.** 콘텐츠 → 이유 → 상세(이유 재확인 · 내 상태 · 정보 · Cube 예고) → 저장 → 내 공간(리스트 · 지도) → 외부 지도 → 현장 Cube. 각 화면이 실제 코드로 존재하고 서로 링크로 이어진다. 10/12 Gap Analysis의 가장 큰 끊김(이유가 상세에서 사라짐, 상세에서 방문을 못 남김)은 해소됐다.
- **연결부: 세 군데가 비어 있다.** ① 로그인에서 사라지는 첫 행동 ② 저장 뒤 돌아올 계기 ③ 방문 · Cube 앞에서 필요한 마지막 정보(운영시간 · Cube 위치). 셋 다 새 기능이 아니라 **기존 기능에 의도 · 데이터 · 문장을 이어 붙이는 일**이다.
- **추천 · 사람은 이 Journey의 주인공이 아니다(지금).** Golden Path는 이 둘 없이 끝까지 간다. 공간이 늘어나면 6-7 단계에서 "함께 소개된 공간" 옆에 서게 될 기능이다.
