## 1. Executive Summary

### 한 줄 진단

> **SpaceCube는 "왜 이 공간인가"를 만드는 능력(큐레이션 선정 이유, 운영자 이야기, 현장 Cube)은 이미 레퍼런스 수준이다. 그런데 그 이유가 화면을 넘어갈 때마다 끊기고, 마음이 움직인 순간(읽기 → 저장 → 방문)을 붙잡는 장치가 약하다. 게다가 지금 HOME과 추천은 공간 30곳 이상을 전제로 설계됐는데, 실제 공개 공간은 6곳이다.**

### 숫자로 본 현재 규모 [DB]

| 항목 | 값 | 의미 |
|---|---|---|
| 공개 공간(EditorialSpace PUBLISHED, 시연 제외) | **6곳** | 6곳 모두 `cubeAvailable=true`, 즉 전부 Partner |
| 공개 공간의 태그(`tags`) | **6곳 모두 0개** | 추천은 `category` 한 단어로만 매칭된다 |
| CURATION / PEOPLE / THOUGHT | 6 / 3 / 3편 | CURATION 6편은 모두 2026-10-04 같은 날 발행 |
| 큐레이션에 담긴 공간 중 선정 이유(note)가 있는 비율 | 14/14 | 이유 데이터는 충분하다 |
| 실사용자 / 공개 공간 저장 / 내 공간 기록 | 19명 / **1건** / 2건(1명) | 저장·기록 루프가 아직 돌지 않는다 |
| Cube 방문 Record | 78건 | 현장 경험은 실제로 쌓였다 |
| 최근 30일 Discovery 이벤트(상세 조회·지도 클릭) | 2건 | 웹 발견 트래픽은 사실상 없다 |

### 가장 부족한 경험(최종 질문에 대한 답)

**"읽고 마음이 움직였는데, 그다음이 이어지지 않는다."**

1. CURATION 카드와 HOME 카드에는 "왜 골랐는지"가 있다. 그런데 정작 결정하는 화면인 Space Detail에서는 그 이유가 사라진다.
2. 비로그인 방문자가 저장을 누르면 로그인 화면으로 갔다가 돌아온다. 하지만 저장은 되지 않은 채다. Instagram에 링크를 공유해도 미리보기 이미지가 없다.
3. 저장한 공간에 실제로 다녀와도, 그 사실을 남기려면 내 공간 깊숙이 들어가야 한다. 그렇게 남긴 기록도 추천이 바뀌는 느낌으로 돌아오지 않는다.

### 최우선 TOP 3(10장)

1. **Space Detail을 "이 공간의 목차 + 내 기록의 입구"로** — Atlas Obscura·Eater의 "이야기 → 장소" 원리 + Mapstr의 to-try/tried 원리
2. **Instagram 도착 준비(공유 미리보기 · 저장 의도 보존 · 유입 출처)** — Instagram 매거진·favkorea의 "썸네일 한 장이 클릭을 만든다" 원리 + Google Maps 저장의 "누른 순간 담긴다" 원리
3. **규모에 맞는 HOME(같은 공간 반복 접기 · CURATION 앞세우기)** — LongBlack·Magazine B의 "적게, 하나에 집중" 원리

개인화 추천 고도화(재방문 반영, 이름 기반 추천 이유)는 방향은 맞다. 다만 **공간 6곳·저장 1건에서는 체감도 검증도 불가능하다.** 그래서 NEXT로 둔다. 같은 이유로 공간 태그 입력(운영 작업)을 NOW에 넣는다.

## 2. 현재 SpaceCube 실제 구현 구조

### 2-1. 한 장 요약(실제 코드 기준)

```text

                     ┊
       ┌──────── CONTENT ─────────┐

       └──────────────┬────────────┘
                      ▼
 HOME(선반 12종) / 검색(/search) ───────▶ SPACE DETAIL (/spaces/[slug])      ✅
   · 엄선한 공간(개인 정렬)                   · 소개·정보·지도 링크·저장
   · 관심 지역 · 비슷한 사람                  · Partner: Episode 목록 + 운영자 이야기
   · 지역/테마/새로 소개/함께한 공간          · "이 공간이 소개된 이야기"(맨 아래)
                      │                       ┊ 선정 이유 없음 · 내 상태 없음
                      ▼                       ┊
                    SAVE ··· 비로그인: 로그인 후 저장 안 됨(재클릭 필요)
                      │
                      ▼
            내 공간(/archive) 리스트 | 지도      ✅
              · 가보고 싶은 곳 / 다녀온 곳 / 또 간 곳(N번)
              · 공간별 상세: 방문 타임라인(내 방문 + Cube 방문 합침) · 사진 · 한 줄 · wantAgain
                      ┊
     VISIT(실제 방문) ┊ ← Space Detail에서는 "다녀왔어요"를 남길 수 없음(부분 구현)
                      ┊
     PARTNER 공간 ── QR ─▶ 대표 Episode ─▶ 방명록 ─▶ 완료      ✅ (현장 경험 자체는 견고)
                      │       (로그인 시 Record 생성 → 내 공간에 "Cube로 N번")
                      │       ┊ 완료 화면 → 웹 Space Detail·저장으로 가는 다리 없음
                      ▼
            PERSONALIZATION ··· 신호: 방문 Record(공간당 최신 1건 × 1~5점) + 저장 + 내 공간 기록
                      ┊         이유: "내 공간들과 비슷한 결"(고정 문구) — HOME에서는 큐레이션 이유에 가려짐
                      ┊         재방문 횟수·wantAgain은 쓰지 않음, 공간 태그 0개
                      ▼
               DISCOVERY(HOME 정렬)  ← 공간 6곳 중 저장·방문한 곳을 빼면 남는 후보가 거의 없음

 별도 축:
 PEOPLE(사용자) ─ HOME "취향이 비슷한 사람" 줄(아바타·닉네임) ─▶ 공개 프로필 /u/[handle]
                  (다녀온 공간 / 가보고 싶은 공간 그리드, 겹치는 공간 표시, 따라가기)  ✅
                  ┊ "나와 비슷한 사람들이 좋아한 공간" 선반은 누가 골랐는지 숨김(부분 구현)
```

## 3. 레퍼런스에서 반복해서 보이는 핵심 원리

기능이 아니라 원리만 남겼다. 오른쪽 열은 그 원리가 SpaceCube에서 어느 화면에 해당하는지다.

| # | 원리 | 대표 레퍼런스 | SpaceCube 위치 |
|---|---|---|---|
| P1 | **이유가 장소보다 먼저 온다** — 장소 정보보다 "왜 여기인가"가 클릭을 만든다 | Atlas Obscura, Eater, Infatuation, Magazine B, Fare | CURATION note, Space Detail |
| P2 | **이유는 화면을 넘어가도 따라온다** — 목록에서 본 한 줄이 상세에서도 첫 문단이 된다 | Eater 맵/가이드, Atlas Obscura 장소 페이지 | HOME 카드 → Space Detail |
| P3 | **누른 순간 담긴다** — 저장 비용이 0에 가깝다 | Google Maps 저장, Mapstr | SaveButton |
| P4 | **저장과 방문은 다른 상태이고, 방문은 쌓인다** | Mapstr(to try/tried), Polarsteps, been | 내 공간 상태 3종 |
| P5 | **같은 풀, 다른 순서 + 이름 있는 이유** — "○○을 봤으니" | Netflix, 29CM | HOME 엄선 선반 |
| P6 | **추천한 사람이 신뢰의 단위** | World of Mouth, Spotted by Locals, Rexby, Corner | 사람 줄, 공개 프로필 |
| P7 | **그 자리에 있어야 열린다 + 방문 전후에도 이어진다** | Adventure Lab, Bloomberg Connects | Cube Episode, 완료 화면 |
| P8 | **파트너 표시는 "경험할 수 있는 곳"이지 순위가 아니다** | Standart To Share | PartnerMark, /cube-spaces |

## 4. SpaceCube가 이미 잘하고 있는 것

1. **선정 이유가 데이터로 존재한다.** 큐레이션에 담긴 공간 14곳 모두 note가 있다 [DB]. HOME 카드와 검색 결과 카드도 이 note를 이유로 쓴다. Eater나 Infatuation이 사람 손으로 하는 일을 이미 구조로 갖고 있다. (P1)
2. **콘텐츠와 공간이 같은 저장으로 이어진다.** CURATION, PEOPLE, THOUGHT 본문의 공간 블록에 저장 버튼이 있고 Space Detail로 이어진다. 매거진류(AROUND, BRIQUE, ANTIEGG)에는 없는 구조다.
3. **방문이 쌓이는 기록.** 가보고 싶어요 → 다녀왔어요 → 또 갔어요(날짜·메모·사진)가 있다. 웹 방문과 Cube 방문을 한 타임라인으로 합친 것은 Mapstr에도 없다. (P4)
4. **현장 경험 자체가 견고하다.** QR → 대표 Episode → 방명록 흐름, SpaceUnlock, 비로그인 참여, Record 78건 [DB]. Adventure Lab의 "도착해야 열림"을 이미 갖고 있다. (P7)
5. **Partner 원칙을 지킨다.** 랭킹 가산이 없고 "등급이 아니다"를 코드 주석과 화면에서 지킨다. Standart To Share와 같은 원칙이다. (P8)
6. **사람 추천의 이유가 공간이다.** "북눅을 함께 다녀왔어요". 팔로워 수가 아니라 겹친 공간이 이유다. World of Mouth의 원리와 같은 방향이다. (P6)
7. **지도를 검색이 아니라 기록 보기로 썼다.** 내 공간 지도에는 위치 권한·주변 검색·거리순이 없다(`ArchiveMap.tsx`). Google Maps와 경쟁하지 않는 올바른 한정이다.

## 10. 최우선 TOP 3

선정 조건: 서로 겹치지 않을 것, 첫 방문자가 실제로 느끼는 변화일 것, 지금 데이터(공간 6·저장 1)에서도 의미가 있을 것, 콘텐츠 운영 부담을 늘리지 않을 것, 이미 있는 데이터·API를 재사용할 것.

### TOP 1. Space Detail = "이 공간의 목차 + 내 기록의 입구" (후보 1 + 2)

- **왜 지금?** 모든 유입(HOME·검색·CURATION·Instagram)이 결국 이 화면에 도착한다. 공간이 6곳뿐이라 상세 하나하나의 품질이 곧 서비스의 품질이다. note 14개, 운영자 이야기, Episode가 **이미 DB에 있는데 보이지 않는다.**
- **왜 이 기능?** 최종본이 Space Detail 목차화를 NEXT로 뒀을 때는 콘텐츠가 없었다. 지금은 공개 공간 6곳 중 5곳에 큐레이션이 2~4편씩 붙어 있다 [DB]. 새 데이터 없이 배치만 바꾸면 Atlas Obscura의 "이유 → 장소" 구조가 완성된다. "다녀왔어요"는 내 공간에 이미 있는 액션을 상세로 옮기는 일이라 비용이 작다.
- **무엇을 검증하나?** 상세 조회 → 저장 전환율, 상세 → 연결 이야기 클릭률, 상세에서 남긴 "다녀왔어요" 수(지금은 경로 자체가 없어 0).
- **원리 출처:** Atlas Obscura · Eater(P1·P2), Mapstr(P4). **SpaceCube다운 이유:** 정보 페이지가 아니라 "이 공간을 왜 골랐는지"부터 말하는 매거진의 상세이면서, 동시에 "내가 머문 기록"이 시작되는 곳이 된다. 다른 지도 서비스의 상세에는 이 두 가지가 없다.

### TOP 2. Instagram 도착 준비 — 공유 미리보기 · 저장 의도 보존 · 유입 출처 (후보 3 + 4 + 5)

- **왜 지금?** NOW 운영 계획(주간 CURATION + Instagram 동시 배포)이 이번 달에 시작된다. 이 준비 없이 배포하면 첫 4주의 유입을 **잃고, 세지도 못한다.**
- **왜 이 기능?** 셋 다 "처음 온 사람의 첫 행동"을 지키는 장치다. 공유 미리보기는 클릭을, 의도 보존은 첫 저장을, 출처 기록은 검증을 지킨다. 모두 기존 화면에 붙이는 작업이고 새 화면이 아니다.
- **무엇을 검증하나?** Instagram 출처 방문 수 → Space Detail 도달 → 저장(로그인 포함) 퍼널. "웹 원본 → SNS 파생" 운영 가설이 맞는지.
- **원리 출처:** Blah Blah · favkorea(P10), Google Maps 저장(P3). **SpaceCube다운 이유:** Instagram을 본체로 키우지 않고, 웹이 원본이자 축적 장소라는 원칙을 실제로 작동하게 만든다.

### TOP 3. 규모에 맞는 HOME (후보 6)

- **왜 지금?** 비로그인 HOME에서 같은 6곳이 엄선 · 새로 소개 · 연남 · 함께한 공간 선반에 반복된다. Instagram에서 처음 온 사람에게 "공간이 몇 개 없다"는 인상을 준다. 같은 6곳을 한 번씩, 이유와 함께 보여주면 "골랐다"는 인상이 된다.
- **왜 이 기능?** 대부분 **이미 있는 관리자 선반 토글**로 바로 할 수 있다(운영). 코드는 "새로 보여줄 공간이 없으면 선반을 접는" 규칙 하나다. 공간이 늘면 자동으로 선반이 다시 열리므로 나중에 되돌릴 작업이 없다.
- **무엇을 검증하나?** HOME → Space Detail 클릭률, HOME 스크롤 깊이 대비 클릭, CURATION 선반 클릭.
- **원리 출처:** LongBlack · Magazine B(P9), Bluer(선별의 신뢰). **SpaceCube다운 이유:** 공간 수 경쟁을 하지 않는다는 원칙을 HOME 첫인상에서 지킨다.

> **제외한 것과 이유:** 추천 정합화(후보 8)는 비용이 작고 방향도 맞다. 하지만 저장 1건·태그 0에서는 사용자도 운영자도 차이를 볼 수 없다. TOP 3로 저장과 방문 데이터가 생긴 뒤(NEXT)에 하는 것이 맞다. Cube CTA 통일(후보 7 중 D1)은 TOP 3에 넣을 만큼 크지 않은 **부채 정리**라서 NOW 목록에 따로 둔다.

## 13. SpaceCube가 하지 말아야 할 것

최종본 12장 목록은 그대로 유효하다. 이번 Gap Analysis에서 **새로 생긴 유혹** 세 가지만 덧붙인다.

1. **지도를 "탐색 화면"으로 키우기.** 관리자 지도 · 내 공간 지도로 좌표가 쌓이면 "공간 지도 둘러보기"를 만들고 싶어진다. 6곳짜리 지도는 빈약해 보이고, 30곳이 되면 네이버지도와 비교당한다. 좌표는 **기록(내 공간)과 편집(CURATION 지도)**에만 쓴다.
2. **선반을 더 만들어 HOME 채우기.** 선반 12종은 공간 30곳(fixture)을 기준으로 설계됐다. 공급이 부족할 때 선반을 늘리면 반복만 늘어난다. 공간이 늘기 전까지는 선반을 줄이는 쪽이 맞다.
3. **개인화를 먼저 정교하게 만들기.** 저장 1건인 시점의 추천 알고리즘 작업은 검증할 수 없는 작업이다. 신호를 정직하게 만드는 정리(NEXT)까지만 하고, 정교화는 데이터가 생긴 뒤에 한다.

## 14. 최종 결론

### 현재 SpaceCube를 실제로 썼을 때 가장 부족한 경험은?

> **"이 공간이 왜 좋은지 읽고 마음이 움직인 순간이, 다음 화면 · 다음 행동으로 이어지지 않는 것."**

이유는 큐레이션 카드까지만 따라오고 Space Detail에서 사라진다. 저장은 로그인 화면에서 사라진다. 방문은 상세에서 남길 수 없다. Cube 방문은 끝나면 웹으로 돌아오지 않는다. 기능은 각각 있는데 **연결부**가 비어 있다.

### 이미 있는 기능을 최대한 쓰면서 다음에 무엇을 해야 하나?

1. **Space Detail에 이미 DB에 있는 "고른 이유"와 "내 기록"을 올린다.** (TOP 1)
   - 새 데이터 0. 기존 note · 이야기 관계 · 아카이브 API 재사용
2. **처음 온 사람의 첫 클릭과 첫 저장을 지킨다.** (TOP 2)
   - 기존 metadata · callbackUrl · DiscoveryEvent 확장
3. **HOME을 지금 규모에 맞춰 접는다.** (TOP 3)
   - 기존 관리자 선반 토글 + 규칙 하나

그리고 코드가 아니라 **태그 입력과 주간 발행**이 이 셋의 효과를 결정한다.

### 그 개선은 어떤 레퍼런스의 어떤 원리이며, 왜 SpaceCube다운가?

| 개선 | 레퍼런스 · 원리 | 왜 SpaceCube다운가 |
|---|---|---|
| Space Detail 목차 + 내 기록 | Atlas Obscura · Eater: **이유가 장소보다 먼저, 화면을 넘어가도 따라온다** / Mapstr: **저장과 방문은 다른 상태이고 방문은 쌓인다** | 지도 서비스의 상세는 "어디 있나"를 말한다. SpaceCube 상세는 "왜 여기인가"와 "내가 여기 몇 번 머물렀나"를 말한다 |
| Instagram 도착 준비 | Instagram 매거진 · favkorea: **썸네일 한 장과 한 줄이 링크를 연다** / Google Maps 저장: **누른 순간 담긴다** | SNS를 본체로 키우지 않는다. 웹이 원본이고 축적 장소라는 원칙을 실제로 작동하게 한다 |
| 규모에 맞는 HOME | LongBlack · Magazine B: **적게, 하나에 집중** / Bluer: **선별됐다는 신뢰** | 공간 수로 경쟁하지 않는다. 6곳을 "고른 6곳"으로 보이게 한다 |

**한 문장 판단:** 지금 SpaceCube에 필요한 것은 새 레이어가 아니다. **이미 가진 이유(note)와 이미 가진 기록(Archive · Cube)을 서로 잇는 연결부 세 군데**다. 그 연결이 생겨야 콘텐츠 발행이 저장으로, 저장이 방문 기록으로, 기록이 (NEXT의) 개인화 추천으로 이어진다.

## 부록. 핵심 질문 Q1~Q15 짧은 답

| Q | 답 |
|---|---|
| Q1 가장 강한 부분 | **큐레이션 선정 이유(note) + 현장 Cube + 웹 · Cube 방문을 합친 기록.** 매거진(이유)과 Mapstr(기록)과 Bloomberg(현장)를 한 제품이 다 가진 경우는 레퍼런스 중에 없다 |
| Q2 가장 약한 부분 | 기능 사이의 연결부. 이유 → 상세, 클릭 → 저장, 저장 → 방문 기록, Cube → 웹. 그리고 공급(공간 6 · 태그 0) |
| Q3 HOME은 발견을 잘하나 | 구조는 발견 허브다. 하지만 지금은 **같은 6곳이 여러 선반에 반복되는 진열**에 가깝다. 다양성 재정렬로는 풀 6곳의 반복을 못 막는다 |
| Q4 콘텐츠가 공간 발견에 연결되나 | **연결된다.** 본문 공간 블록 + note + 저장. 끊긴 쪽은 반대 방향(공간 → 콘텐츠)이다. 상세에서 콘텐츠가 맨 아래 제목으로만 보인다 |
| Q5 Space Detail은 정보 페이지인가 목차인가 | **목차의 재료는 다 있는 정보 페이지.** 순서와 "고른 이유" 한 블록이 빠져 있다 |
| Q6 Archive vs 네이버지도 · Mapstr | 다른 점: Cube 방문 자동 합산, 방문 타임라인, 저장 → 추천 신호, 개인 기록(링크 · 사진). 아직 없는 차별점: **발견한 맥락**(어느 큐레이션에서 왔나). 지도는 Mapstr와 비슷한 수준이지만 일부러 기록 보기로 한정했다 |
| Q7 Archive 지도는 핀에서 끝나나 | 지금은 핀 + 상태 + 횟수다. **기반은 있다** — `ArchiveVisit.visitedOn`, 방문 횟수, `lastAt`. 기간 축(올해/전체)과 카드의 "마지막 방문"만 붙이면 "어디에 머물러 왔나"로 넘어간다. 개인 기록과 비 Partner 공간은 좌표가 없다는 구조적 한계가 있다(D9) |
| Q8 추천이 개인화됐다고 느끼나 | **못 느낀다.** 이유가 고정 문구이고, HOME에서는 큐레이션 note에 가려지며, 태그 0 · 공간 6이라 순서 차이도 작다 |
| Q9 추천 이유를 구체화할 여지 | **크다.** 사람 추천은 이미 공간 이름 이유를 쓴다(`rankPeople.ts:47-58`). 같은 패턴을 공간 추천에 쓰면 된다 — 앵커 = 가장 강한 신호를 준 공간(재방문 > 방문 > 저장)의 이름 |
| Q10 사람 추천은 사람 발견인가 공간 발견인가 | 의도는 공간 발견이다(HOME은 공간 선반 먼저, 사람 줄은 아바타만). 하지만 공간 선반이 **누가 골랐는지를 숨겨서** WoM의 신뢰 원리가 빠졌다. 반대로 프로필에는 팔로워 숫자가 있어 사람 발견 쪽 요소가 남아 있다 |
| Q11 Cube는 여전히 중요한가 | **가장 중요하다.** 공개 공간 6/6이 Cube 공간이고 실데이터 대부분이 Cube에서 나온다. 끊긴 것은 Cube → 웹의 다리다 |
| Q12 Partner가 무엇이 다른지 이해되나 | `/cube-spaces`에서는 이해된다. 하지만 지금은 모든 공간이 Partner라 구분이 성립하지 않는다. Standart 원칙(가산 없음)은 지키고 있다. 상세 상단의 한 문장 안내가 필요하다 |
| Q13 lat/lng를 사용자 기능에 더 쓸까 | 내 공간 지도(완료) → 시간 축 보강(NEXT) → CURATION 지도(LATER) 순서. 지역 이야기 · 주변 · 지도 탐색은 하지 않는다 |
| Q14 Instagram 유입을 붙잡을 준비가 됐나 | **안 됐다.** 콘텐츠 → 공간 → 저장 경로 자체는 있다. 하지만 미리보기 없음, 비로그인 저장 손실, 출처 미기록 때문에 첫 방문이 새고, 샌 것도 셀 수 없다 |
| Q15 하나만 만든다면 | **Space Detail 목차화 + 내 기록 입구(TOP 1).** 모든 경로가 도착하는 화면이고, 새 데이터 없이 이미 있는 이유와 기록을 보여주는 일이라 비용 대비 체감이 가장 크다. TOP 2는 유입이 실제로 시작되기 직전에 반드시 해야 하므로 바로 다음이다 |
