## 0. 검증 범위 — 무엇을 직접 봤고 무엇을 못 봤는가

| 구분 | 상태 | 방법 |
|---|---|---|
| 비로그인 첫 방문자 (HOME · 검색 · 상세 · CURATION · PEOPLE · ABOUT · 404) | **직접 확인** | 앱 내장 브라우저로 운영 사이트 클릭·스크롤·DOM 측정 |
| 데스크톱(약 1024px 창) / 모바일 에뮬레이션(375×812) | **직접 확인** (HOME만 모바일) | 내장 브라우저 뷰포트 에뮬레이션 — 실기기 아님 |
| 저장 클릭 → 로그인 이동 (`sc_intent` 부여) | **직접 확인** | 로그인 화면까지만 |
| QR `/c/GC-006` → Episode 열람 | **직접 확인** | 아래 "운영 데이터에 남은 흔적" 참고 |
| 로그인 후 저장 · 의도 복원 · 다녀왔어요 · 내 공간 | **미검증 (코드 분석만)** | 로그인(Google/Kakao)은 인증 정보 입력이 필요해 수행하지 않음 |
| 방명록 포스트잇 작성 · 재방문 | **미검증** | 로그인·운영 데이터 작성이 필요 |
| LCP / INP | **측정 못함** | 내장 브라우저에서 LCP 항목이 비어 있었음. 추정값은 적지 않음 |
| 키보드 탐색 · 스크린리더 | **코드 분석만** | 포커스 트랩·ESC는 소스에서 확인, 실제 키 입력 시험은 못 함 |
| 실기기 모바일 · 느린 네트워크 | **미검증** | |

> 내장 브라우저는 숨김 상태에서 스트리밍 페이지의 텍스트 추출이 `LOADING_`로 남는 경우가 있어, 화면 스크린샷으로 렌더를 먼저 확정한 뒤 DOM을 읽었다. 이는 도구 특성이며 사이트 문제로 보지 않는다.

**운영 데이터에 남은 흔적(정직한 공개):** QR 시험으로 `/c/GC-006`을 한 번 열었다(녹화버튼). 이 때문에 운영 DB에 **SpaceScan 1건(비로그인 anonId)** 과 Episode 조회 기록이 생겼을 수 있다. 이번 작업은 "운영 DB 수정 금지"였으므로 삭제하지 않았다. 필요하면 해당 시각(2026-10-24)의 GC-006 anon 기록만 제외하면 된다. 그 외 `/c/GC-001~006`은 HTML만 받아(JS 미실행) 스캔 로그가 생기지 않는다.

## 3. 첫인상 5초 / 15초 / 30초

- **5초 (01):** 검은 헤더 + 큰 사진 + "대화보다 음악이 먼저 들리는 곳". 잘 만든 에디토리얼 사이트로는 보이지만 "무슨 서비스인가"는 전달되지 않는다. 지도·장소 서비스와의 차이도 없다.
- **15초:** "망원의 공간 / 지역 망원 / 공간 17곳 · 큐레이션 6편 / 지금은 망원 지역만 이용할 수 있어요. … 일부 공간은 시연용입니다." — 이 안내는 정직하지만, **서비스 소개보다 먼저 면책 문구**를 읽게 된다.
- **30초:** 선반을 내려 보면 사진 위주 카드가 계속 이어진다. 카드를 눌러야 알 수 있는 정보가 많고, 같은 카드가 계속 나와 "데이터가 적다"는 인상이 먼저 생긴다. QR·큐브는 맨 끝 섹션 "GONGGANCUBE EXPERIENCE … QR 스캔하기"에서야 등장한다(약 6,000px 아래).

질문별 답:
1. 어떤 서비스인지 한눈에? **아니오** (HOME에 정의 문장 없음)
2. 지도·검색과의 차이? **HOME에서는 전달 안 됨.** `/about` 첫 문단("대부분의 서비스가 … 공간에 도착한 뒤 조금 더 깊이 바라보는 경험")이 정확한 차별점인데 가려져 있다
3. 콘텐츠 기반 발견 가치? 일부 — CURATION 슬라이드가 그 역할
4. 처음 할 일이 명확? 검색창이 보이지만 "무엇을 검색하라"는 힌트는 약함(placeholder "지역, 공간, 취향을 검색해보세요")
5. 정보 과다? 첫 화면은 오히려 절제되어 좋음. 과다는 **스크롤 뒤쪽 반복**
6. LATEST 이미지/제목 매력? 이미지는 좋고 제목은 시적이지만 구체성이 낮음("대화보다 음악이 먼저 들리는 곳"은 어떤 공간인지 알기 어려움)
7. CURATION/STORY/추천 차이? 섹션명은 있지만 **설명이 없다.** "STORY" 안에 PEOPLE/THOUGHT가 섞이고 번호(PEOPLE 006 · 시연용)가 앞서 읽기 부담
8. 상단/하단 탐색? 헤더는 로고+검색+햄버거, 모바일은 하단 3탭. 단순해서 좋다. 그러나 `/about`·CURATION·STORY가 모두 햄버거 안
9. "지역: 망원"과 실제 콘텐츠 일관성? **깨짐** — 망원 컬렉션 안에 연남(북눅·턴다운서비스·내면의 발견)·용인(아카커피룸) 실제 공간이 "연남 · LP카페", "용인 처인구 · 카페"로 표기된 채 섞임
10. 가상/실제 혼재 신뢰도? "시연용 공간" 라벨이 모든 가상 카드에 붙어 있어 구분은 됨. 다만 **6곳의 실제 공간 중 일부만 라벨 없음 = 실제**라는 규칙이 암묵적이고, 시연용 사진이 실제 장소 사진처럼 보인다(가설, §8)

## 4. HOME 심층

**LATEST(슬라이드)**
- 3장(CURATION 003 / PEOPLE 002 / THOUGHT 002)이 전부 실제 Partner 사진. 가로 사진·크롭 자연스러움 양호(01).
- 시연 콘텐츠 7~10번은 LATEST에서 빠지고(세로 사진 규칙) 공간 선반에서만 보인다 — **슬라이드가 3장뿐이라 "최근 올라온"에 비해 빈약**하다.
- 모바일에서 슬라이드 점 버튼 크기 14×24px(탭 영역 작음).

**공간 선반 — 반복 (직접 측정)**
- HOME의 `/spaces/*` 링크 126개 = 카드 63장(카드당 링크 2개) / 고유 공간 17곳.
- 가장 많이 반복: `쪽지와 음반` 5회, `초록 서가`·`찻잔 선반`·`북눅 연남`·`다시점`·`아카커피룸`·`만년필과 우체통`·`턴다운서비스` 등 각 4회. 최소는 `슬라이드 룸` 2회.
- 한 화면(약 12개 선반)을 지나는 동안 같은 카드를 4번 만나는 구조 → "데이터 부족" 신호. 선반 제목은 유형·태그 규칙 기반이라 **같은 공간이 서로 다른 이유로 반복**된다. 예: "누군가와 오래 이야기하기 좋은 곳"에 녹화버튼·찻잔 선반·턴다운서비스·초록 서가·쪽지와 음반이 함께 들어간다(공통 근거가 약함 — 가설: 태그 매칭이 느슨).
- "내면의 발견"(연남)은 소개·한 줄 설명이 없고 표지 이미지가 밝은 책 표지라 시연 사진들과 톤이 다르다.
- "개인화 여부" 표시: 비로그인에서 "지금 둘러보기 좋은 공간"(날짜 seed 다양성 선택) — 문구가 개인화를 주장하지 않아 정확하다. 로그인 후 "회원님을 위해 엄선한 공간"으로 바뀌는 것은 코드 확인만.
- 중간의 CTA 카드("가보고 싶은 공간을 담아 두면 … 로그인")는 좋지만 "취향에 맞는 공간을 더 골라 드려요"가 **약속에 비해 근거(추천 기준) 설명이 없음**.

**시각 위계:** 첫 화면은 좋다. 이후 카드 크기·강조가 모두 비슷해 시선이 머물 곳이 없다("눈에 띄는 한 곳" 부재).

## 5. 검색·지역·테마

직접 확인(03·04·05):
- `카페` → "카페 관련 공간 10곳", 중복 없음, 사진 없는 공간 없음.
- `허공xyz` → "관련 공간을 찾지 못했어요. 다른 말로 검색하거나, 아래에서 지역·테마를 골라 보세요." + 추천 지역/테마. **막다른 길 없음 — 양호.**
- `연남` → "“연남” 관련 공간 3곳" 위에 **"지역 · 연남 · 준비 중"** 행이 있고 아래에 북눅 연남·내면의 발견·턴다운서비스 카드가 보인다. "준비 중"인 지역의 공간이 열려 있어 모순이다.
- 추천 지역 목록: 망원(공간 17곳, 별 아이콘) / 연남·후암·서촌·성수 "준비 중" + "그 밖의 지역 — 용인 처인구 준비 중". `/?area=연남`은 `/`로 redirect.
- CURATION 목록 필터에는 **망원 · 연남 · 용인 처인구**가 모두 클릭 가능 (15) → 지역 잠금 규칙과 불일치.

**Partner(연남·용인)를 망원에서 탐색할 때의 신뢰 문제와 제안 (데이터 정확성 유지)**
1. 카드 지역 문구는 그대로 두되(주소·좌표 불변) 컬렉션 제목을 "망원의 공간" 대신 **"망원 시연 컬렉션"**으로 바꾸면 17곳이 망원이라는 오독을 막는다. (이미 "망원동 시연 컬렉션" 선반명이 코드에 있음 — HOME 지역 제목과 통일)
2. 지역 안내 문구를 "시연용 공간은 망원으로 분류돼 있어요. 실제 공간은 소재지를 표시합니다."로 구체화. 현재 문구는 "일부 공간은 시연용입니다"뿐.
3. 검색의 "연남 · 준비 중" 행은 연남 결과가 있을 때 "연남 · 공간 3곳"으로 열거나 숨긴다(둘 중 하나로 통일).
4. 변경 범위: 문구/RegionPicker 한 곳. 회귀 위험: 낮음.

## 6. 공간 상세

확인한 화면: 북눅 연남(06, 실제 Partner), 초록 서가(08, 시연). 모달(17)도 확인.

**좋은 점**
- 사진 → 이름·유형 → 한 줄 → [저장하기][다녀왔어요] → 고른 이유 → 소개 → 정보 → 공간큐브 EP → 이야기 → 관련 공간 순서가 읽기 쉽다.
- 시연 공간은 최상단 한 줄("시연용 공간 — … 실제 장소가 아닙니다. 지역 “망원”은 시연용 분류예요.")로 명확히 고지.
- EP 목록: 제목은 보이되 잠금 아이콘 + "이 이야기는 공간에서 열 수 있어요 / 공간을 방문해 QR을 인식해보세요" 안내 — QR을 찍어야 하는 이유가 UI에 드러남(코드 `PartnerEpisodeList.tsx`).
- 모달: 포커스 트랩, ESC·바깥 클릭·X로 닫기, `aria-modal`, 닫으면 HOME 스크롤 복원 (닫은 뒤 `scrollY=500` 복원 확인).

**문제**
- **소개문 "공간 소개를 준비하고 있어요."** — 북눅·내면의 발견·아카커피룸 상세에서 직접 확인(06). 실제 Partner 상세가 "빈 칸" 인상을 줌 (P1, 내용 필요 — 지어내지 않음).
- 태그가 형용사형("감각 있는", "독특한", "영감 있는", "다시 오고 싶은")이라 **근거 없는 주관 평가**로 읽힌다. 아카커피룸·내면의 발견에서 확인.
- **다녀왔어요**를 첫 클릭으로 누르면 상세 화면에서 취소할 수 없다(코드: 취소는 "또 갔어요"로 남긴 재방문 1건만 `undoVisit`). 첫 기록의 정정은 "내 기록"에서 해야 한다 — 잘못 누름에 취약.
- **저장 성공 피드백:** 버튼이 "저장됨"으로 바뀌고 "내 공간에 저장한 곳이에요. 내 기록 보기 →" 줄이 생기지만 토스트·`내 공간으로 이동` 같은 명확한 다음 행동은 없다(코드 분석, 실제 클릭 미검증).
- 모달 열림 중 **뒤 화면이 푸터 쪽으로 스크롤된 것처럼 보임**(관찰: `scrollY` 6178/6946 → 닫으면 500으로 복원). 시각적으로 어색하나 닫으면 복원되므로 P2. 원인은 가설(`loading.tsx` 전환 중 문서 높이 변동).
- 공간 카드에 링크가 2개씩(하나는 `tabindex=-1`) 존재 — 스크린리더가 같은 항목을 두 번 읽을 수 있음(가설).
- 데드 코드: `SaveButton`/`SpaceRelation`의 `mock` 분기("임시(fixture) 공간")는 이제 아무 곳에서도 `mock`을 넘기지 않는다 — 시연 공간이 DB 공간이 된 뒤 남은 잔재. 동작에는 영향 없음, 혼동 방지를 위해 정리 권장(P2).

## 7. 로그인·저장·아카이브

직접 확인한 부분: 비로그인 상태에서 상세의 **저장하기** → `/login?callbackUrl=/spaces/booknook-yeonnam?sc_intent=<uuid>` 로 이동(07). 의도(`sc_intent`)가 주소에 실려 가는 것을 확인.

| 항목 | 판정 |
|---|---|
| 1. 왜 로그인해야 하는지 | **약함.** 제목 "로그인하고 내 공간을 이어가세요" — 신규 사용자에게 "이어가다"는 이미 쓰던 사람에게 하는 말. 부제 "저장한 공간과 다녀온 기록이 한곳에 쌓여요."는 작은 글씨 |
| 2. 로그인 후 자동 완료 | 코드상 구현(`pendingIntent.ts` 1회용 + 이미 저장됨 판정). **실제 로그인 후 동작은 미검증** |
| 3. 성공 피드백 | 위 §6 — 코드상 문장 안내 있음, 이동 CTA 없음 |
| 4. 새로고침 후 유지 | 코드상 서버 `initialSaved` — 미검증 |
| 5. 실제/가상 공간 저장 동작 일치 | 코드상 동일(시연 공간도 DB 공간이라 실제 저장, KPI는 `isDemo=false`만 집계). `mock` 분기는 죽은 코드. **"화면에서만 바뀌는" 저장 경로는 현재 코드에 도달 불가**(`mock`을 넘기는 호출 없음) |
| 6~7. 내 공간 표시·상태 이해 | 미검증 |
| 8. 빈 아카이브의 다음 행동 | 비로그인은 로그인 벽만(14). 로그인 후 빈 상태 **미검증** |
| 9. 지도에서 좌표 없는 공간 누락 | 알려진 한계(handoff): 가상 공간 11곳은 좌표 없어 지도에 안 나옴(목록엔 나옴). **미검증이지만 handoff와 일치** — 심사 시 "내 공간 지도"에서 시연 공간을 저장하면 지도가 비어 보일 수 있음 |
| 10. 시연 데이터가 KPI에 섞임 | 코드 정책상 제외(`demoSpaces.ts`, KPI는 `isDemo=false`). 실측 미검증 |

**좋은 점**

## 10. 시각 디자인 일관성

- HOME·검색·상세·CURATION·모달: 검정 헤더, 흑백, 타이포 중심 — **일관됨.**
- **404(09)**: "공간큐브 / 404 · > 이 공간은 존재하지 않아 · 삭제됐거나 잘못된 주소야 · [[ 홈으로 ]]" — 터미널 풍 + **반말**. 사이트의 존댓말("~해요/합니다")과 어긋나고 에디토리얼 톤도 아님. 심사위원이 잘못된 링크를 열면 마주치는 첫 오류 화면.
- **QR/로그인 계열** 변수 `--dim #888880`(밝은 배경 약 3.3:1) — 작은 글씨 보조 문구가 WCAG AA(4.5:1)에 못 미침. 에디토리얼 `--ed-dim #6f6f6f`는 약 4.8:1로 통과. (계산값 — 대비 측정 도구 미사용)
- 로그인 화면은 별도 크림 배경 + Kakao 노랑 — 허용 가능하지만 헤더만 검정으로 이어짐.
- 모바일 탭 영역: 슬라이드 점 14×24px, 푸터 링크 높이 16px(터치 영역 부족). 상단 "← 홈" 55×16px.
- 포커스 링은 `editorial-bleed`/모달 범위에만 정의(`globals.css` 307행대) — 비에디토리얼 화면(QR·로그인)은 브라우저 기본값에 의존(가설).
- 카드 대체 텍스트: 이미지 `alt` 누락 0. 공간 카드 이미지 alt가 공간명만이라 정보량은 적지만 충분.

## 11. 접근성 · 성능 · 안정성 (확인 가능한 것만)

- 로케일 `lang="ko"`, `h1` 존재, `main` 존재. 모달 `role=dialog aria-modal`, ESC·포커스 트랩 구현(코드).
- 슬라이드: `aria-roledescription="carousel"`, 일시정지 시 `aria-live` 전환(코드). `prefers-reduced-motion` 규칙 존재.
- **메타/공유:** 모든 페이지가 `og:title="공간큐브"`, `og:description` 사이트 공통문구 — 공간·콘텐츠 상세에서도 동일. **`og:image` 없음.** 카카오톡·메신저로 링크를 보내면 제목/사진 없는 평범한 미리보기(P1).
- `robots.txt`, `sitemap.xml`이 404 HTML을 반환(둘 다 HTTP 200 + HTML로 관찰) — 검색엔진 안내 없음(P2). 존재하지 않는 `/spaces/nope`도 HTTP 200으로 응답 — soft-404(P2).
- 잘못된 큐브 코드(`/c/…`)·비활성 큐브·미연결 큐브 안내 문구는 코드에 있으나 시각 확인은 안 함.
- Core Web Vitals: LCP 측정 불가 → 수치 없음. CLS 0은 관측 구간 한정.
- 개인정보/운영 데이터 위험: 비로그인에서 확인한 페이지에 개인 식별정보 없음. Partner 6곳 주소·운영시간은 공개 정보(원본 DB 값).
